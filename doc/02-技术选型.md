# 技术选型（2026-09-01 拍板）

## 结论

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Go | 单二进制、低资源、标准库覆盖需求 |
| 前端 | Vue3 + Element Plus | 文件列表/图片预览组件成熟 |
| 台账存储 | 本地 JSON 文件（原子写） | 数据量小；后续可换 SQLite，接口不变 |
| 部署形态 | 单 exe + 本地 Web UI（内嵌前端） | 双击即用，免安装 |
| 端口 | 18765（可配） | 固定端口实现单实例复用 |

## 对比记录

### Go vs Java（老板问过，已对比）

| 维度 | Go | Java (Spring Boot) |
|---|---|---|
| 部署 | 单二进制，无 JVM 依赖 | 要 JVM，fat jar 几十 MB |
| 内存 | 常驻 30-80 MB | 起步 300-500 MB |
| 启动 | 毫秒级 | 秒级 |
| 标准库 | net/http + os + filepath 全内置 | 全要引 Spring 全家桶 |
| 生态 | 够用；SMB/WebDAV 类库偏弱 | 老协议库更丰富成熟 |
| 团队门槛 | 会的人相对少 | 国内团队多 |

**判定**：本项目业务复杂度低、难在部署维护 → Go 完胜。选 Java 仅当「团队只会 Java」或「重度集成老协议生态」。

### 本地 Web vs 桌面壳（C# WPF/WinUI）

| 维度 | Go 单 exe + 本地 Web | C# WPF/WinUI |
|---|---|---|
| 图片预览体验 | 网页网格/懒加载，现成组件 | 自绘管线，工期翻倍 |
| 开发速度 | 快 | 慢 |
| 系统集成（托盘/右键） | 一般（非刚需） | 原生强 |
| 部署 | 一个 exe | .NET 运行时或大包 |

**判定**：核心体验是「浏览 + 看图」，网页形态最快最好。

### 为什么砍掉 rclone / AList

需求不直接路由网盘，只保存自定义路径 → 不需要多存储后端抽象层，砍掉整个重型依赖。

## 前后端形态

- **开发时：分离**。前端 `web/`（Vite dev :5173，`/api/*` 代理到后端），后端 Go 独立跑。
- **运行时：合并**。前端构建产物 `web/dist` 由 `go:embed` 内嵌进 Go 二进制，单进程单端口。
- **仓库：monorepo**。前后端同仓库、分目录。
- **API 边界**：一开始就划死 REST 接口，将来要拆独立部署架构不用动。
