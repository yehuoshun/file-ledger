# 架构设计

> 更新: 2026-11-17（与代码现状对齐；规划中的条目显式标注「未实现」）

## 运行形态

```
浏览器 → http://127.0.0.1:18765
          ├─ /api/*    → Go 后端
          └─ /         → 内嵌前端页面（web/dist，SPA fallback）
```

- 端口固定 18765（config.json 可改）；监听失败 = 已有实例在跑 → 直接开浏览器复用旧实例
- 工作目录 = exe 所在目录（`main.go` 启动时 `os.Chdir`），config.json 与数据都生成在 exe 旁

## API 边界（REST，已实现）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | /api/registry?parent_id=&q=&limit=&offset=&is_dir= | 台账**分页**：`parent_id` 缺省/空 = 顶层（`parent_id IS NULL`），给 uuid = 该文件夹的直接子条目；`q` 按别名/备注/标签名模糊（大小写不敏感，`% _ \` 按字面）；`is_dir=true\|false` 过滤类型；`limit` 默认 50／上限 200、`offset` 默认 0；返回 `{"items":[…],"total":N}`，排序文件夹优先再按别名升序（2026-11-17 起；旧的全量 `[]Entry` 形状已废弃） |
| GET | /api/registry/folders | 全部文件夹的**轻量扁平列表**（只有 `id`/`alias`/`parentId`，不带 `paths`/`tags`），供前端建树、面包屑、子文件夹计数；返回 `{"items":[…],"total":N}` |
| POST | /api/registry | 新增（UUID v7 服务端生成；校验：别名唯一、父存在、类型合法、文件必填路径） |
| PUT | /api/registry/{id} | 更新（id 为 UUID；parentId 可改 = 移动位置） |
| DELETE | /api/registry/{id} | 删除（级联删子） |
| GET | /api/fs/list?path=<绝对路径> | 只读列目录；路径指文件时自动列其所在目录 |
| GET | /api/tags?q=&limit=&offset= | 标签字典**分页**：`q` 名字模糊（大小写不敏感）、`limit` 默认 50／上限 200、`offset` 默认 0；返回 `{"items":[…],"total":N}`，按名称升序 |
| GET | /api/tags?names=a,b,c | 按名字**批量精确取**（≤100 个，逗号分隔，优先于 q/limit/offset）；列表按需补色用，返回 `{"items":[…],"total":N}` |
| POST | /api/tags | 新增标签：名字必填、唯一、≤32 字；`bg/fg` 留空则由后端按调色板分配（201 / 400 / 409） |
| PUT | /api/tags/{id} | 改名 / 改色；**改名在同一事务里把条目上的旧名换成新名**；`bg/fg` 留空沿用旧配色 |
| DELETE | /api/tags/{id} | 删除标签，并**在同一事务里把它从所有条目上剔除**（204 / 404） |

错误统一返回 `{"error": "中文消息"}`，前端直接展示。`GET /api/registry` 的分页参数不合法（`limit` 非 1..200 的整数、`offset` 负数、`is_dir` 非 true/false）一律 400；`parent_id` 不是合法 UUID 时按「查不到」处理（200 + 空 items），不把脏值送进 SQL。`/api/fs/list` 的参数/响应/错误码约定见 `doc/05-进度.md`「步骤 4 接口契约」。

条目保存（POST/PUT `/api/registry`）时，`tags` 先归一（trim、丢空、按首次出现去重、单个 ≤32 字），再把字典里没有的标签名自动登记进 `tag` 表——所以前端输入新标签直接保存即可，不需要先调 `/api/tags`。

**未实现（规划）**：`GET /api/config`（设置页接后端）、`GET /api/fs/status`（盘符在线离线探测，步骤 5）。

## 数据模型（台账 Entry，现状）

| 字段 | 说明 | 约束 |
|---|---|---|
| id | 主键 | UUID v7，服务端生成，天然按时间排序 |
| alias | 别名 | 必填、同一父级下唯一、排序键 |
| parent_id | 所属文件夹 | 自引用，NULL = 顶层；可移动 |
| is_dir | 是否文件夹 | 创建后不可改 |
| size | 大小（字符串） | 仅文件手填；文件夹为空（大小是子条目合计的概念） |
| note | 备注 | 可选 |
| tags | 标签名数组 | jsonb 数组（可选）；存**名字**而非 id；写入前归一，且名字必须在 `tag` 字典里（保存时自动登记） |
| paths | 路径数组 | `[{"type":"local|mount|virtual","path":"…"}]`；**文件夹为空**；文件至少一条 |

时间戳 `created_at` / `updated_at` 由服务端维护。存储：PostgreSQL `file_ledger` 库，`pgx/v5` 纯 Go 驱动。

**连接使用方式**：`pgx.Conn` 不是并发安全的（两个请求同时查询会报 `conn busy / failed to deallocate cached statement(s)`），因此 `internal/db/conn.go` 给单连接加了互斥，所有 store 走 `db.Conn`（Query/QueryRow/Exec/Begin 在 rows 迭代结束、Scan、Commit/Rollback 时放锁）。个人单机足够；没上官方 `pgxpool` 是因为它依赖 `jackc/puddle`，本机 go proxy 不通、拉不到依赖。

## 标签字典（tag 表，2026-11-17 后端化）

标签不再写死在前端，由数据库字典管理（`internal/tag`、`internal/api/tags.go`）：

| 字段 | 说明 |
|---|---|
| id | UUID v7，服务端生成 |
| name | 标签名，唯一，≤32 字符（`tag.MaxNameRunes`） |
| bg / fg | 背景色 / 文字色（`#rrggbb`），新建留空按 4 组调色板轮转分配；只改名时保留旧配色 |
| created_at | 创建时间 |

- **预置 6 个标签**（建表时 `ON CONFLICT DO NOTHING` 幂等灌入）：工作、重要、娱乐、文档、项目、备份（配色沿用前端旧值）
- **条目只存标签名**：改名 / 删标签时后端在同一事务里用 jsonb 数组操作同步 `registry.tags`，历史数据不用迁移
- **不一��性加载**（老板 2026-11-17 要求，防标签量大后卡顿）：前端 `useTags` 只缓存**用到的**标签颜色，
  - `colorOf(name)` 同步取色（缓存未命中给兜底灰 `#e4e7ed/#303133`）
  - `ensureColors(names)` 表格渲染前按需批量补色（只请求缓存里没有的，按 100 分块）
  - `searchTags(q, limit)` 给选择器下拉按需搜索（默认 20 条，输入防抖）
  - `fetchPage(q, page, pageSize)` 给设置页「标签管理」做服务端分页（可新增 / 改名 / 改色 / 删除）

## 安全设计

- **防路径穿越**（已实现，`internal/fsx`）：只接受绝对路径、拒绝含 `..` 的段、`Clean` 后复查；纯只读，不读文件内容、不写入
- 服务只监听 127.0.0.1；PostgreSQL 同样只监听本机
- 只读锁（read_only）：未实现，预留
- 符号链接逃逸检测：未实现（后续批次）

## 关键决策记录

- **文件夹 = 虚拟文件夹 = 纯分类容器**（2026-11-07 定版）：不填路径、不出「浏览」，只是分类容器
- 台账**全量加载**到前端组树：数据量小（个人台账），换来切文件夹零请求
- 目录浏览只列台账条目自己的路径：文件夹没有路径（见上条推断）
- 目录列表上限 1000 条：超出返回 `truncated=true` + 实际 `total`，避免大目录卡死
- 虚拟路径不碰文件系统：查台账直接返回「仅记录」，不做 fs 操作
- 缩略图：Go 纯库生成 + 缓存目录 + 过期清理（批次 2 细化）
- 数据库选型：老板本地已有 PgSQL 实例（2026-09-13 确认），使用 pgx 驱动
- **单连接 + 互斥串行化**（2026-11-17）：pgx.Conn 并发会报 conn busy，而 pgxpool 的依赖 puddle 需联网拉不到 → 自己包一层互斥（等价连接池大小 1）；本地单用户、每次请求都是毫秒级查询，串行化代价可忽略
